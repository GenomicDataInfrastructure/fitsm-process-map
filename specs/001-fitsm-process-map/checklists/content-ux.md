# Content Fidelity and Map/Frame UX Checklist: FitSM Process Map

**Purpose**: Formal review gate on the quality of the requirements in `spec.md` for two areas:
(1) fidelity to the FitSM standard and traceability to its documents, and (2) the subway-style
map, the detail frame and their accessibility. A lighter pass covers maintainability and
licensing. Each item asks whether a requirement is written well enough to implement and test
without guessing; none asks whether the site works.
**Created**: 2026-10-03
**Feature**: [spec.md](../spec.md) (plan: [plan.md](../plan.md), data model:
[data-model.md](../data-model.md), contracts: [contracts/](../contracts/))

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

**How to read an item**: the question names what should be written in the spec; the tag in
brackets gives the quality dimension and where to look (`Spec §FR-nnn`, `Spec US-n` for a user
story, `[Gap]` when nothing is written yet). Several decisions that the spec leaves open are
answered in `plan.md`, `data-model.md` or `contracts/`; an item still fails if the spec itself
is silent, because the spec is what acceptance tests are written against.

## Requirement Completeness: Content Fidelity

- [x] CHK001 Does the spec list which text fields must be verbatim quotations of FitSM (objective, requirement text, task text, activity name, procedure steps, record definition, interface description, flow item) and which may be the project's own wording? Without the list, a reviewer cannot tell a permitted paraphrase from a violation of FR-018. [Completeness, Spec §FR-018]
- [x] CHK002 Is the minimum content of a source reference defined for display (document code, version, section or identifier; page optional) so that "carries a reference" in FR-017 has one testable form? [Completeness, Spec §FR-017]
- [x] CHK003 Does the spec define which FitSM-2 tables establish an interface for FR-002 (the per-process "key interfaces" table, the inputs/outputs tables, or both), and what to do when a pair appears in one but not the other? This decides how many connections the map has. [Completeness, Ambiguity, Spec §FR-002]
- [x] CHK004 Are inputs and outputs whose source or target is not a FitSM process (customers, suppliers, top management, users) addressed: shown, excluded, or shown without a connection? FR-010 only covers flows between two processes. [Gap, Spec §FR-010]
- [x] CHK005 Is the rule for deriving a process's records from its outputs stated precisely enough for two maintainers to derive the same list (which outputs count as records, what to do with an output that has no FitSM-0 definition)? [Completeness, Spec Assumptions, Spec §FR-019]
- [x] CHK006 Are the role kinds that carry generic tasks enumerated (process owner, process manager, case owner, process staff), and is the display for a process-specific role with no generic tasks defined? [Completeness, Spec §FR-011]
- [x] CHK007 Is the behaviour defined for an activity for which FitSM-2 gives no procedure steps, and for a role for which FitSM-3 gives no count? [Gap, Spec §FR-011, §FR-012]
- [x] CHK008 Does the spec state how FitSM-internal cross-references inside quoted text ("see clause 6.2", "as defined in FitSM-0") are to be shown, so that quotation stays intact and still makes sense out of context? [Gap, Spec §FR-018]
- [x] CHK009 Is the handling of a process that a later edition removes (not merely renames or merges) specified, so that shared links to its code still resolve to something? [Gap, Spec Edge Cases]
- [x] CHK010 Is "latest published edition" (FR-021) defined with a rule for patch releases (for example "the version shown on fitsm.eu/downloads on the date in the changelog"), so that two reviewers agree on which document is current? [Clarity, Spec §FR-021]
- [x] CHK011 Are the general requirements (GR1–GR7) given the same completeness rules as process requirements (identifier, text, source, group name), so FR-007a is not weaker than FR-009? [Consistency, Spec §FR-007a, §FR-009]

## Requirement Clarity: Content Fidelity

- [x] CHK012 Is "describes the same interface differently" (FR-020) defined: any difference in wording, or a difference in meaning as judged by the maintainer? The answer decides how many "FitSM disagrees" notes appear. [Clarity, Spec §FR-020]
- [x] CHK013 Is the wording and placement of the interpretation label standardised across its three cases (derived records, multiple interface descriptions, study-aid lines), or may each look different? FR-019 says "visibly labelled" without saying how. [Clarity, Consistency, Spec §FR-019]
- [x] CHK014 Is the on-page term for "databases and records" fixed (the user's words, or FitSM-0's terms "record" and "information store"), and is the chosen term used consistently in FR-009, FR-013 and the Key Entities? [Terminology, Spec §FR-009, §FR-013]
- [x] CHK015 Are "connection" (map), "interface" (FitSM) and "relationship" (User Story 2 title) defined as one concept with one canonical term, or are they deliberately distinct? A reviewer should not have to infer that they are the same thing. [Terminology, Spec US-2, §FR-002, §FR-010]

## Requirement Completeness: Map and Frame

- [x] CHK018 Are the visual properties that make the map "in the style of a public transport map" named (segments only horizontal, vertical or 45°; uniform station glyphs; line labels; no arrowheads), so that FR-001 can be judged rather than felt? [Clarity, Measurability, Spec §FR-001]
- [x] CHK019 Does the spec state whether every process must belong to at least one line, and the allowed number of lines overall and per process? A process on no line would have only neutral connections, which FR-003 does not address. [Gap, Spec §FR-003]
- [x] CHK020 When two connected processes share more than one line, is the rule for choosing the connection's colour written down? [Ambiguity, Spec §FR-003]
- [x] CHK021 Is a legend required (not "for example"), and are its contents specified (line name, colour sample, transfer style, "study aid" label)? FR-006 offers a label "for example", which is not a requirement. [Clarity, Spec §FR-006]
- [x] CHK022 Is the neutral "transfer" style required to differ from line styles in shape (dash or weight), not only in colour, so that FR-003 and FR-006 agree? [Consistency, Spec §FR-003, §FR-006]
- [x] CHK023 Is the station highlight for the selected item (FR-005) defined by something other than colour (ring thickness, outline, size), in line with "information MUST NOT be shown by colour alone"? [Consistency, Spec §FR-005, Constitution Constraints]
- [x] CHK024 Is it specified which station, if any, is highlighted while a role, activity, record, interface or the general requirements view is shown? User Story 3 scenario 3 implies the owning process stays highlighted; FR-005 says only "the selected one". [Consistency, Spec §FR-005, US-3]
- [x] CHK025 Is the breakpoint for "narrow screens" (FR-008) quantified in pixels or by a named device class, and is the choice between scrolling and panning the map (Edge Cases) made? [Clarity, Spec §FR-008, Spec Edge Cases]
- [x] CHK026 Are the order and headings of the sections in the process view (objective, requirements, roles, records, activities) binding, or only the set of contents? FR-009 lists them in one order without saying so. [Clarity, Spec §FR-009]
- [x] CHK027 Is the frame's content when nothing is selected defined (introduction, edition line, instructions)? FR-024 covers only the not-found case. [Gap, Spec §FR-024]
- [x] CHK028 Are loading and load-failure states defined for the page (what the visitor sees while content loads, and if a content file fails to load)? [Gap]
- [x] CHK029 Are empty states defined for a process with no derived records, a role with no process-specific tasks, and an interface with descriptions but no flows? [Edge Case, Gap, Spec §FR-009, §FR-011, §FR-010]
- [x] CHK030 Does the spec say how long content (for example 15 requirements plus 8 roles) is handled in the frame: frame scrolls independently, page scrolls, or sections collapse? [Gap, Spec §FR-008]
- [x] CHK031 Is the back control's behaviour defined for every view, including when the visitor arrived by direct link and there is no previous item? User Story 3 scenario 3 covers role and activity only. [Completeness, Spec §FR-015, US-3]
- [x] CHK032 Are canonical address forms and redirects specified in the spec (for example `#PM-ISRM` resolving to `#ISRM-PM`, lower-case codes, former codes), or only in `contracts/url-hash.md`? Shared links are public behaviour and belong in the acceptance criteria. [Gap, Spec §FR-022, §FR-023]
- [x] CHK033 Does FR-024's not-found behaviour extend to unknown role, activity, record and interface addresses, not only unknown process codes? [Coverage, Spec §FR-024]
- [x] CHK034 Is the location and label of the general requirements entry point (FR-007a) specified well enough to find in a usability test (for example "in the page header, labelled 'General requirements'")? [Clarity, Spec §FR-007a]
- [x] CHK035 Are hover and touch behaviours specified or explicitly excluded (tooltips on stations, hover on connections), given that phone visitors have no hover? [Gap, Spec §FR-033]
- [x] CHK036 Is the map's sizing specified: fixed canvas, scale to the container width, or user zoom, and does the station label remain the full code and name at every size (FR-001) or may it shorten? [Gap, Conflict, Spec §FR-001, §FR-033]
- [x] CHK037 Is it stated whether the browser tab title changes with the selection, which matters for screen-reader users and for shared links? [Gap, Spec §FR-023]

## Accessibility Requirements

- [x] CHK038 Are the WCAG 2.1 AA thresholds written as numbers (4.5:1 for text, 3:1 for line strokes, station glyphs and focus indicators), so that "meet WCAG 2.1 AA contrast" in FR-033 is testable without interpretation? [Clarity, Measurability, Spec §FR-033]
- [x] CHK039 Are screen-reader requirements defined for the map (accessible name of each station and connection, announcement of the frame update on selection, the map's own role and description)? The spec covers keyboard only. [Gap, Spec §FR-007]
- [x] CHK040 Is the keyboard tab order specified (map before frame; station order; connections before or after stations), and is the required visibility of the focus indicator quantified? [Gap, Spec §FR-007]
- [x] CHK041 Are minimum target sizes for stations and connection hit areas specified for touch (WCAG 2.5.8 gives 24×24 CSS px as the AA floor)? [Gap, Spec §FR-033]
- [x] CHK042 Is reflow at 200% and 400% browser zoom (WCAG 1.4.4, 1.4.10) addressed for the map and the frame, or explicitly treated as covered by the narrow-screen requirement? [Gap, Spec §FR-008, §FR-033]
- [x] CHK043 Is it stated whether line colours must also be distinguishable under common colour-vision deficiencies, or whether the name label alone satisfies FR-006? [Clarity, Spec §FR-006]
- [x] CHK044 Are dark-mode, high-contrast-mode and reduced-motion behaviours specified or explicitly out of scope? [Gap, Boundary]

## Requirement Consistency and Conflicts

- [x] CHK050 Do the Line entity ("drawn as a route joining their stations") and FR-002 ("MUST NOT draw connections FitSM does not define") agree about a line whose member processes have no FitSM interface between them? If not, one must be reworded. [Conflict, Spec Key Entities, §FR-002]
- [x] CHK051 Is the frame placement in FR-008 ("beside the map, to the right") consistent with the Assumptions ("right frame means beside the map on wide screens") and with the user's request, including right-to-left languages being out of scope? [Consistency, Spec §FR-008, Spec Assumptions]
- [x] CHK052 Do FR-022 ("openable by a link that contains its FitSM code") and FR-007a (general requirements openable by direct link) use the same link convention, given that "GR" is not a process code? [Consistency, Spec §FR-022, §FR-007a]
- [x] CHK053 Is the number "14 FitSM processes" (FR-001) tied to the edition in `edition.json` rather than hard-coded, so that FR-001 and FR-028 do not conflict when a future edition changes the count? [Consistency, Spec §FR-001, §FR-028]

## Notes

- Mark items `[x]` only after review confirms the requirement-quality criterion is satisfied
- Leave items unchecked when they still require clarification, correction, or reviewer evaluation
- Items tagged `[Gap]` usually need a sentence added to `spec.md`; items tagged `[Clarity]` or
  `[Ambiguity]` usually need an existing sentence made precise; `[Conflict]` items need one of
  the two sentences changed
- Where the plan or a contract already answers an item, the fix is to lift that answer into
  the spec so acceptance tests can cite it
- `/speckit-implement` reads checklist state but does not modify markers
